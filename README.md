# 离线会话清理（Windows 桌面版）

针对 DSH 0.2.2-rc.5 的 JSONL 存储。**永久删除一个已归档、无父子关系的独立会话的当前日志，不是清理整个工作区，也不是安全擦除。** 插件没有定时任务，没有批量或在线删除按钮。

## 使用

1. 保留整个插件目录，在 DSH 的「插件 → 添加插件」选择该本地目录；无需运行 npm。启动器会优先寻找桌面版配套的独立 Node 运行时，再查找 PATH 上的 Node；若都没有，请从 https://nodejs.org/ 安装 Node.js 22 LTS 或更高版本。不要使用 DSH 内置终端来运行助手。
2. 如要保留备份，先自行导出。找到目标会话，归档并等待所有工作停止；在侧栏「视图」选择「仅显示已归档」或「全部对话」，找到目标行。在该行的「⋯」菜单选「准备离线清理…」，复制的是会话 ID，不是聊天正文。若剪贴板不可用，使用内置「复制 Session ID」。
3. 保持 DSH 打开，从资源管理器双击本目录的「清理助手.cmd」。粘贴 ID。助手仅在本机请求预览，列出绝对文件位置和日志长度。**此时没有删除会话**；取消请直接回车或关窗。
4. 退出前回到目标行，再查看「准备离线清理…」通知里的标题和 ID，独立核对预览中的目标、路径和字节数。不要仅从剪贴板重复粘贴来确认。保持会话归档，完整退出所有 DSH Desktop、CLI 和后台 Host；不要使用另一个实例修改归档、重开会话或直接编辑数据。在助手完成前不要重启 DSH。十分钟内在同一助手里重新输入完整 ID 才执行不可逆删除；失败请不要手工删目录。
5. 成功后再打开 DSH。保留空的会话目录、归档记录和其他非日志数据；旧索引或界面引用可能暂时仍能显示该标题，但日志不可再恢复。这里显示的是删除文件的长度，不是保证回收的物理磁盘空间。

## 范围与拒绝条件

仅为本机、Windows 固定 NTFS 卷、JSONL v4 单一规范日志（原始或 Zstandard）实现。历史多代日志、未归档、子代理、分叉、拥有子会话、特殊或不确定的存储布局、硬链接/符号链接、文件在预览后变更、无法判断停机等情况均拒绝。不会删除工作区、其他会话、全局索引、上传附件、备份或云副本，也不执行数据库压缩。请勿在共享数据根、多用户网络卷或有其他绕过插件的写入程序的配置中使用。

## 权限与数据流

浏览器只复制已选择的 ID，没有文件路径参数、执行权或模型工具。Host 通过 DSH 的归档集合和持久化快照核实选择；仅在用户运行独立助手时预览。握手与签名计划落在当前 Windows 用户的 `%LOCALAPPDATA%\DshSessionCleaner-v1`，不在浏览器或共享临时目录中，依赖正常的 Windows 用户目录访问控制；不要与其他账号共享这个目录。计划保存 ID、路径、元数据和目标哈希，不保存聊天正文。Host 每次激活和收到取消归档事件时更新失效标记；这不是 DSH 共享数据库锁，不防绕开插件直接改库。命令行助手只有在明确二次确认后才请求核心离线操作。计划文件失效后没有授权效力；助手/插件均不递归删除目录。

首次安装后，请完全退出并重新打开 DSH，以加载当前版本。插件使用模拟数据测试，未在真实用户会话上试删。若 DSH 存储格式或默认后端发生变化，请勿绕过拒绝检查。
